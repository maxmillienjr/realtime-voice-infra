# Capability status

_Verified against `main @ 66369ac` on 2026-09-15._

This repository is read before it is run. Its README, `CLAUDE.md`, `.context/` and `.agents/`
describe a transport layer with three pillars — AudioWorklet capture, backpressure-aware
streaming, and session-scoped encryption — and for each pillar the prose runs ahead of the
code in a specific, checkable way. This file is the correction: one row per capability the
documentation claims, what is actually behind it at HEAD, and — where the answer is "not
fully" — the PRD in `docs/prd/` that owns finishing it.

The rule that keeps it honest lives in `.context/conventions.md`: a capability claim in
`README.md`, `CLAUDE.md`, `.context/` or `.agents/` must be true of the code at HEAD. Anything
aspirational either gets a row here or goes to `docs/prd/`.

## How to read the status column

| Status        | Means                                                                                                                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `implemented` | Wired at HEAD and shown working by a committed test, a CI run, or a hand verification whose date and method the row records.                                                                        |
| `stubbed`     | The code exists and is unit-tested, but the production path never reaches it, or it performs no real work when reached.                                                                             |
| `planned`     | Not built. The owner column names the PRD; until that PRD ships, the prose either says "planned" or says nothing.                                                                                   |
| `broken`      | Built and reachable, and the documented guarantee does not hold at HEAD. The row records the observed behaviour.                                                                                    |
| `removed`     | Provisioned and never used; the provisioning is gone. No row carries it yet — P0-B will create the first.                                                                                           |
| `unverified`  | Could not be exercised from this repository on 2026-09-15 — today that means the browser half, which no test or workflow runs. Treated as not proven. A row here is never promoted by reading code. |

`stubbed` and `broken` are the rows to watch. `stubbed` is a protocol with a unit test and no
production path to it; `broken` is a sentence in `.context/` that a five-line probe falsifies.

## What this means for a reader

The server half is real. Session keys are generated, derived and stored; frames are decrypted
under a deterministic-IV AES-GCM scheme with the rollover, tamper and cross-session cases
tested; the JWT is single-use; 100 concurrent encrypted sessions pass through a GitHub runner
weekly with every frame acked. Rows 5, 7, 8, 9, 14, 16, 22 and 24–31 are that half.

The browser half has never completed a frame round trip. Rows 1, 2, 3, 6 and 12 are the
client, and the only one shown working is the header configuration. The client sends
plaintext because nothing gives it a key, so the README quickstart — `docker compose up`,
start the client, grant the microphone — ends in `DECRYPT_FAILED` and a disconnect after
about 100 ms of audio. No CI path would notice, because no CI path runs the client. P1-A is
the first piece of work in the backlog for that reason, and it forces a decision the original
spec left open: how the client comes to hold the session key.

The backpressure pillar has never fired. Row 11 is a correct hysteresis tracker behind a
router that releases every frame before the next one can arrive. The 2026-09-14 load run's
`pauses=0` is not evidence the server keeps up; it is evidence the counter cannot climb. P1-B
owns giving the server something to be slow at.

Two sentences in `.context/` are falsified by a probe rather than merely unbacked: replay
detection rewinds (row 10) and shutdown drains nothing (row 15). Both have small fixes and
their own PRDs. Row 26 is the one row an automated check should own, and does not yet.

Rows 2, 14 and 28 carry no owner because they are true, and rows 5, 7, 8, 9, 16, 24, 25, 29
carry none because they are done. Inventing a PRD id for a working thing would put backlog
rows in the index that nobody has agreed to.

## Keeping this file true

Nothing lints prose. What keeps this file honest is that it is short, every row names a
file and a line, and `.context/conventions.md` requires a pull request that moves a row to
move it here in the same change. `yarn lint:docs` resolves every `path:line` citation against
`git ls-files` and range-checks it, so a citation into a file that shrank or moved fails CI
instead of misleading a reader. If a row's evidence no longer resolves, the row is wrong —
fix it rather than working around it.
